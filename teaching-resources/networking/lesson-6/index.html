Move the Boundary

Learn subnetting by moving the IPv4 network/host boundary and watching the ranges change. There are no marks, no timer and no hidden tricks. Read the explanation, press the buttons, move the slider and replay any step until the pattern makes sense.

Keep only the ideas we need

From routing to the address boundary

Routing tables describe destinations as networks. That is why an IPv4 address needs a network portion and a host portion. This first section is deliberately short: it connects the lecture to the subnetting activity without repeating earlier switching, ARP or encapsulation lessons.

Routing uses network destinationsIPv4 has 32 bitsThe prefix marks a boundary

Three statements to carry into subnetting

Read these before moving on. If they make sense, subnetting becomes much less mysterious.

RoutingRoute to a networkA router can use one prefix for many hosts instead of storing one route per computer.
IPv432 bitsHumans normally write them as four decimal octets such as 192.168.6.10.
Prefix/24 means 24 network bitsThe remaining 8 bits are available for addresses inside that network.
Mask255.255.255.0This is another way to show the same /24 boundary.
Subnetting is not a new address format. It is the act of choosing where the network/host boundary sits. In this lesson we start with the familiar 192.168.6.0/24 network from the practical plan and move that boundary.

Special addresses still follow the same rule

The host portion gives several addresses special meanings.

network

Host bits all 0

Identifies the network itself. For 192.168.6.0/24, the network address is 192.168.6.0.

broadcast

Host bits all 1

Targets every host in that IP network. For 192.168.6.0/24, it is 192.168.6.255.

0.0.0.0

Startup source

Used in the lecture example when a host does not yet have an IP address.

127.0.0.1

Loopback

Sends traffic back to the same computer for local testing.

Now move inside the last octet

Starting with a /24 network, move the slider towards /30. Every step borrows one more host bit to create more, smaller subnets.

/24
/24 — larger host space/30 — very small host space
Original /24 network bitsBorrowed for subnettingRemaining host bits
Direction matters: moving from /24 to /25 uses one more bit for identifying the network/subnet and leaves one fewer bit for hosts. More subnet bits → more subnets. Fewer host bits → fewer usable host addresses in each subnet.

Why routers care about prefixes

The same notation used in subnetting also appears in routing tables.

192.168.6.64/26

A routing-table entry like this describes a whole destination network. A router does not need a separate entry for .65, .66, .67 and every other host in that range.

Keep the mental model

Prefix: where the network boundary sits.

Subnet: one address range created by that boundary.

Network address: first address in the range.

Broadcast: last address in the range.

Usable hosts: addresses between those boundaries.

Stop here before formal subnetting drills. The goal of Lesson 6 is to understand the structure and recognise the pattern. More advanced subnet design can build on this visual model later.

Core idea: an IPv4 prefix marks the boundary between network bits and host bits. Moving that boundary changes the size and number of address ranges. Learn the picture first; calculate after the pattern makes sense.
